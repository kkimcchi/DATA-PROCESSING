# 런던 시간별 → 일별 변환 계획안

이 문서는 `london_merged.csv`(시간별)를 일별 데이터로 변환하기 위한 **계획안**입니다.
아직 실제 변환은 실행하지 않았고, 원본 데이터도 수정하지 않습니다. 집계 규칙의
근거는 [`hourly_to_daily_aggregation_rules.md`](./hourly_to_daily_aggregation_rules.md)를
따르되, 그 문서 하단 "적용 사례: 런던 자전거 공유 데이터셋" 절에서 확정한 규칙을
그대로 씁니다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 입력 파일 | `data/london_merged.csv` (17,414행, 10컬럼, 시간별) |
| 출력 파일 (실행 시 생성 예정, 아직 미생성) | `data/london_daily.csv` (제안 경로 — 실행 단계에서 확정) |
| 원본 데이터 | **읽기 전용으로만 사용, 수정/삭제 없음.** 변환 결과는 새 파일로 생성 |
| 그룹핑 키 | `timestamp`에서 파생한 날짜(`dteday`) |

## 2. 처리 파이프라인 (실행 시 순서)

1. `timestamp`를 datetime으로 파싱
2. `dteday`(날짜), `yr`(연), `mnth`(월), `weekday`(요일) 파생
3. `workingday` 파생 (아래 3-4절 기준)
4. `n_hours_recorded`(그 날 실제 기록된 시간 수) 계산
5. `dteday` 기준으로 그룹핑 → 컬럼별 집계 규칙 적용 (4절)
6. carry-over 대상 컬럼(`is_holiday`, `is_weekend`, `season`) 사전 검증 —
   날짜별 `nunique() == 1`인지 확인 (5절)
7. 결과를 `dteday` 오름차순으로 정렬, 일련번호(`instant`) 재부여
8. 변환 리포트 산출 (7절) 및 파일 저장

## 3. 신규 파생 컬럼 정의

| 컬럼명 | 산출 방법 | 요청 근거 |
|---|---|---|
| `dteday` | `timestamp.dt.date` | 일별 그룹핑 키 (구조상 필수) |
| `yr` | `timestamp.dt.year` | "timestamp에서 연을 뽑아줘" |
| `mnth` | `timestamp.dt.month` (1~12) | "timestamp에서 월을 뽑아줘" |
| `weekday` | `(timestamp.dt.dayofweek + 1) % 7` → **0=일요일 ~ 6=토요일** | "timestamp에서 요일을 뽑아줘". pandas 기본(`dt.dayofweek`)은 월요일=0이지만, 워싱턴 `day.csv`를 역산 검증한 결과 그쪽은 **일요일=0** 인코딩이었음(예: 2011-01-01 토요일 → weekday=6, 2011-01-02 일요일 → weekday=0). 워싱턴과 동일한 인코딩으로 맞추기 위해 위 변환식 사용 |
| `workingday` | `1 if (is_holiday == 0) and (is_weekend == 0) else 0` | "주말도 휴일도 아닌 날을 workingday=1로" — 워싱턴의 `workingday` 정의(공휴일도 주말도 아닌 날)와 동일한 로직 |
| `n_hours_recorded` | 그 날짜에 실제로 존재하는 원본 행 수 (`groupby('dteday').size()`) | "하루에 몇 시간이 기록됐는지도 컬럼으로 남겨줘" |

## 4. 컬럼별 집계 규칙 (원본 컬럼)

`weather_code`, `season` 등은 **원본 코드 체계·값을 그대로 사용**하고 별도
재매핑/스케일 변환은 하지 않습니다. 집계 방식만 아래 규칙을 적용합니다.

| 원본 컬럼 | 집계 규칙 | 근거 |
|---|---|---|
| `t1`, `t2`, `hum`, `wind_speed` | 평균(mean) | 연속형 관측값 유형 |
| `cnt` | 합계(sum) | 누적/집계량 유형 |
| `is_holiday`, `is_weekend`, `season` | 그대로 복사(carry-over) | 하루 내내 고정된 범주형 (5절에서 검증) |
| `weather_code` | 최빈값, 동률이면 숫자가 큰(더 나쁜) 코드 우선 | 하루 중 변하는 범주형. **검증 불가 캐비앗**은 규칙서 하단 참고 — 코드가 순서형임은 확인했으나 런던엔 대조용 일별 정답 파일이 없어 일치율은 측정 불가. 별도 신뢰도 지표 컬럼은 만들지 않음(요청 반영) |

## 5. carry-over 컬럼 사전 검증 방침

`is_holiday`, `is_weekend`, `season`은 "하루 안에서 값이 안 바뀐다"는 전제로
carry-over 규칙을 쓰므로, 실행 시 날짜별 `nunique() == 1`을 반드시 확인합니다.

- **사전 점검(참고용, read-only로 미리 확인한 결과)**: 730일 전부(100%)
  `is_holiday`, `is_weekend`, `season` 모두 하루 안에서 값이 한 번도 안 바뀜
  → carry-over 규칙을 그대로 적용해도 안전함을 미리 확인.
- 만약 실행 시 값이 갈리는 날이 발견되면(현재는 0건이지만, 실행 스크립트에서도
  재확인 필요), 최빈값을 채택하고 해당 날짜를 별도 경고 목록으로 리포트에 남깁니다.

## 6. 결측 시간(gap) 처리 방침

규칙서의 "결측 시간 처리" 원칙(있는 시간만으로 집계 + `n_hours_recorded` 병기,
날짜를 통째로 버리지 않음)을 그대로 따릅니다.

- **사전 점검(참고용)**: 전체 730일 중
  - 24시간 온전히 기록된 날: 696일
  - 24시간 미만으로 기록된 날: **34일** (9~23시간 범위, 최빈 케이스는 23시간 18일)
  - 24시간 초과(중복 시각 등 이상): 0일
  - 첫날(2015-01-04)·마지막날(2017-01-03) 모두 24시간 온전 — 경계일 문제 없음
- `cnt`(합계 계열)는 `n_hours_recorded < 24`인 날에는 "부분 합"이라는 점을
  분석 시 감안해야 함(규칙서 5절 원칙과 동일).

## 7. 실행 후 산출할 리포트 항목

변환 스크립트 실행 시 아래 항목을 함께 출력합니다.

- 변환 후 총 행 수 (일별 데이터 행 수 = 고유 날짜 수)
- `n_hours_recorded < 24`인 날짜 수(= 24시간이 온전하지 않은 날 수) 및 목록
- (참고용 사전 점검치, 실제 실행 시 재확인) 730일 / 34일

## 8. 출력 파일 컬럼 순서(안)

```
instant, dteday, yr, mnth, weekday, is_holiday, is_weekend, workingday,
season, weather_code, t1, t2, hum, wind_speed, cnt, n_hours_recorded
```

## 9. 원본 데이터 보존 확인

- `data/london_merged.csv`는 이 계획 수립 및 사전 점검 과정에서 **읽기만** 했으며
  수정하지 않았습니다.
- 변환 실행 시에도 원본 파일을 덮어쓰지 않고, 새 출력 파일(`data/london_daily.csv`
  제안)로만 저장합니다.

## 10. 다음 단계

이 계획안 승인 후, 위 규칙대로 실제 변환 스크립트를 작성·실행하고 7절의 리포트
(행 수, 미완결일 수)를 결과와 함께 공유합니다.
